# Ultra·Pro 에이전트 운영 결정

> **2026-09-25 개정 (사용자 결정):** 아래 "PC별 Codex 작업 하나"는 **PC별 Claude Code 에이전트 + `agent_bridge` 무인 루프**로 대체되었다.
> 역할(Ultra 총괄·학습, Pro 데이터·검토)과 규약 문서는 유지한다. S2 에이전트 라벨 허용(사람 우선), S1 합성+실촬영, 허용목록+guard 훅, Ultra만 main push를 채택했다.
> 구현과 운영 방법은 [CLAUDE_OPERATION.md](CLAUDE_OPERATION.md)에 있다. 아래 본문은 결정 경위로 보존한다.

작성: 2026-09-25. 이 문서는 역할과 다음 구현의 명세다. 새 Codex 작업, Claude 호출, 예약 실행, 학습 루프를 이번 문서 작성으로 활성화하지 않는다.

## 결정

**Ultra에 Codex 작업 하나, Pro에 Codex 작업 하나를 유지한다. Ultra가 실험 채택과 학습 실행을 결정하고 Pro가 데이터 검수와 결과 분석을 담당한다.** Claude는 상시 공동 작업자가 아니라 필요할 때 제한된 산출물을 독립 검토하는 후보로 둔다. 별도 총괄 작업은 만들지 않는다.

| 선택 | 장점 | 이 프로젝트에서 추가되는 부담 | 판단 |
|---|---|---|---|
| PC별 Codex 하나 | 기존 하네스·환경·규약을 그대로 사용; 결정과 오류를 추적하기 쉬움 | 두 작업 사이의 파일 계약과 재시작 처리는 여전히 필요 | 현재 채택 |
| Codex 실행 + Claude 독립 검토 | 다른 검토 결과로 누락을 찾는지 비교 가능 | 인증·호출 비용·맥락 전달·검토 충돌·재시도 관리 | 선택적 비교 후 도입 |
| 두 제품이 양쪽에서 동시에 구현·수정 | 독립 작업이 충분하면 병행 가능 | 같은 파일 수정, 실험 중 코드 변경, 상충하는 지시 가능성 증가 | 현재 채택하지 않음 |

Codex는 현재 코드 수정·도구 실행·테스트와 이미 연결된 프로젝트 운영에 적합하다. Claude Code도 비대화형 실행과 구조화 출력, 세션 재개를 제공하므로 검토나 구현을 맡길 수 있다. “Claude는 분석에 더 강하고 Codex는 코딩에 더 강하다”는 식의 성능 우열은 이 프로젝트에서 측정하지 않았다. 현재 선택 근거는 검증된 연결과 운영 복잡도다.

2026-09-25 Ultra에서 확인한 실행 파일은 `codex-cli 0.128.0`, `Claude Code 2.1.170`이다. 설치 확인은 Claude 로그인·사용 한도·Pro 설치 확인 또는 두 제품의 실제 비교 실험을 의미하지 않는다.

## 역할별 읽을 문서

1. [Ultra 작업 지시서](threads/ULTRA_THREAD.md): 학습 실행, 버전 동결, 실험 채택.
2. [Pro 작업 지시서](threads/PRO_THREAD.md): 데이터 검수, CPU 지표 재계산, 다음 실험 제안.
3. [실험 파일 규약](EXPERIMENT_PROTOCOL.md): 두 작업의 공통 인터페이스.
4. [라벨링·전처리 전 데이터 명세](DATA_PREPARATION_SPEC.md): 학습 시작 조건.

두 Codex 대화의 오래된 맥락보다 승인된 파일 버전과 실행 증거를 우선한다. 대화를 새로 만들어도 위 네 문서와 마지막 결정 파일을 읽으면 이어갈 수 있어야 한다. 대화 ID 자체가 데이터나 실험 상태의 저장소는 아니다.

## 현재 자동 교환과 앞으로 필요한 자동 판단

현재 Git/Syncthing/CPU worker는 코드·선택한 데이터·검수본을 전달한다. `ping` 성공은 Pro의 Python worker 응답이지 Pro Codex가 판단을 시작했다는 뜻이 아니다. 수신 폴더에 파일을 쓰는 것만으로 상대 Codex 작업을 깨울 수 없다.

지속 가능한 반복은 다음 순서로 구현한다.

1. **현재 단계:** 기존 두 Codex 작업에서 역할 지시서를 읽고 데이터 게이트와 첫 실험을 수동으로 시작한다. 최초 파일 왕복이 이미 검증된 전송 계층을 재설치할 필요는 없다.
2. **다음 단계:** 실험 패킷 검사기, 수신 확인, 중복 방지 장부, 고정 commit 실행기를 구현하고 중단·재부팅 검사를 통과한다. [규약의 구현 목록](EXPERIMENT_PROTOCOL.md#아직-구현해야-할-것)을 따른다.
3. **그다음:** 각 PC의 로컬 자동화가 새 유효 패킷만 확인하고 해당 PC의 Codex 작업을 실행하게 연결한다. Pro는 새 결과 해시당 검토 한 번, Ultra는 채택된 결정당 학습 한 번을 원칙으로 한다. 같은 상태에는 반복 알림·LLM 호출을 하지 않는다.

Codex 앱의 로컬 자동화는 해당 컴퓨터가 켜져 있고 앱이 실행 중이어야 한다. 전원이 꺼진 동안 작업을 수행하지 않는다. Syncthing·worker 자동 시작과 Codex 앱 실행·자동화 활성화는 별개다. 로그인 후 전송은 재개될 수 있지만 중단된 학습 재개는 체크포인트와 실행 장부를 확인해야 한다.

CLI 방식도 가능하다. `codex exec` 또는 `claude -p`를 **그 PC에서** 실행하는 어댑터가 있어야 한다. 특정 CLI 세션 재개에는 명시적인 세션 ID를 사용한다. 여러 프로젝트가 섞일 수 있는 `--last` 의존은 피한다. 데스크톱 작업 ID와 CLI 세션 ID가 호환된다고 가정하지 않는다. 장치/작업 ID·토큰·로컬 라우팅은 공개 Git에 기록하지 않는다.

초기 자동화 정책 제안은 회차당 소규모 실험 최대 3개, 각 20분, GPU 합계 60분이다. 이는 아직 적용된 제한이나 학습시간 보장이 아니다. 첫 smoke 실측 뒤 `policy.json`에 시간·실험 수·재시도·디스크 한도를 확정하고, 이를 검사하는 실행기가 준비되어야 자동 반복을 켠다. 불충분한 라벨·시간축·사용조건은 자동 학습으로 우회하지 않는다.

## Claude를 추가할 판단 기준

첫 검증 가능한 실험이 나온 뒤, 같은 비식별 결과 묶음 3개로 선택적 비교를 한다. 입력은 설정·집계 지표·오류 설명·코드 diff이며 원본 영상은 기본 입력에서 제외한다. 두 제품에 동일한 질문과 출력 형식을 주고 다음을 기록한다.

- 근거 파일/행을 제시한 유효 결함 수와 실제 수정으로 확인된 누락.
- 사실 오류, 검증셋 누수 제안, 이미 실패한 실험의 반복 여부.
- 채택 가능한 한 가지 변경 제안 수, 응답 시간, 실제 사용량/비용.

Claude가 추가로 찾은 결함이나 더 나은 제안이 비용을 정당화하면 `reviewer`로 도입한다. 같은 문제를 반복 설명한다면 Codex 두 작업 구성을 유지한다. Claude 검토자는 코드·라벨 원본·채택 결정에 쓰기 권한을 갖지 않는 실행 환경을 사용하며, 최종 결정자는 계속 Ultra다. 제품의 도구 자동 승인 옵션만으로 읽기 전용 경계가 보장된다고 가정하지 않는다.
