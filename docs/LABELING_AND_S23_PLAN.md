# 1인 작업 배정과 Galaxy S23 Ultra 재촬영 계획

2026-09-24 확정한 초기 작업 예산이다. 실제 영상 확보와 이용조건 확인 후 시작한다.
실측으로 입증된 최적 시간이 아니라, 현재 두 노트북과 스마트폰으로 실행할 우선 배정이다.
다운로드·설치·독립 원본 확보 대기시간은 아래 수동 작업 시간에 포함하지 않는다.

## 시간 배정: 총 6시간 30분

| 작업 | 시간 | 수행 내용과 완료 기준 |
|---|---:|---|
| S2 기준 맞추기 | 20분 | 공식 정의를 읽고 첫 3개를 함께 비교하는 방식으로 본인 기준 고정 |
| S2 50개 1차 검수 | 200분 | 영상당 평균 4분. 충돌·진입 프레임, 회피 공간, 진입 방향 기록 |
| S2 다음 날 재검수 | 30분 | 기존 답을 가리고 10개 재검수: 애매한 5개 + 나머지에서 무작위 5개 |
| S1 준비·시험 촬영 | 25분 | 화면/폰 고정 15분, 시험 영상 3개 촬영·확인 10분 |
| S1 본 촬영 | 48분 | 독립 원본 24개 × 조건 2개 = 48테이크, 테이크당 1분 배정 |
| S1 USB 복사·대조 | 17분 | 원본 보존, 파일명 대응, 누락·재생 확인, SHA-256 기록 |
| S3 정렬 검수 | 30분 | 균등 표본 20개 20분, 시작·끝·가감속/조향 변화 구간 10분 |
| 휴식 | 20분 | 10분씩 2회 |
| 합계 | **390분** | 실제 작업 370분 + 휴식 20분 |

- **첫날 4시간 10분:** S1 90분 → 휴식 10분 → S3 30분 → S2 기준 20분 + 25개 100분.
- **다음 날 2시간 20분:** S2 나머지 25개 100분 → 휴식 10분 → 가림 재검수 30분.
- 일정은 상대적 작업일이다. 개인 달력에 시간을 예약하거나 실제 작업을 완료한 것은 아니다.
- S2 첫 10개 평균이 4분을 넘거나 20% 이상이 애매하면 같은 시간 안에서 **30개를 정확히 검수**하는 쪽으로 줄인다. 미완료 20개는 미라벨 상태로 둔다.
- 재검수 10개 중 2개 이상에서 사건 정의/방향/선택 프레임이 의미 있게 달라지면, 추가 물량보다 해당 유형의 기준 수정과 재검수를 우선한다. 공식 허용 오차가 없는 항목에 임의 허용 오차를 만들지 않는다.

## 시작 조건과 현재 확보 상태

S2는 DoTA 주석 기반 후보 목록만 확보되어 있다. 실제 사고 영상과 사용 조건 확인이 필요하다.
주석의 anomaly_start를 충돌/진입 시점 정답으로 복사하지 않는다. 공식 프레임 번호와 추출 이미지 파일명의 대응부터 확인한다.
판정할 수 없는 항목은 빈칸과 이유를 남기며 -1을 임의의 정상 클래스로 바꾸지 않는다.
후속 학습에서는 미정의 항목을 마스킹하고, 제출 출력은 별도로 모든 필수 항목을 충족해야 한다.

S1은 **허용된 독립 출처 그룹 24개**가 필요하다. 현재 comma 파일럿 1개 주행을 24개로 자른 것은 24개 독립 원본이 아니다.
동일 사건·주행·재업로드·그 파생은 하나의 origin_group이다. 유사/중복 검토 후 16/4/4개 그룹을 train/validation/test로 확정한다.
현재 기록표의 split은 계획값이며, 출처 확인 전 confirmed_split은 빈칸이다.
출처 확보 방법과 조건은 DATA_ACQUISITION.md / RESOURCE_LICENSES.md를 따른다.

## 촬영 공간과 화면

새 모니터를 구매하지 않고 Pro와 Ultra 화면을 모두 사용한다. 실내에서 정지된 노트북 화면만 촬영한다.
스마트폰을 삼각대나 흔들리지 않는 받침에 고정하고 렌즈 높이를 화면 중앙에 맞춘다.
거리 **25~45cm에서 시작**해 실제 영상이 화면 가로의 70~90%를 차지하게 조정한다. 이 거리는 강제 기준이 아니라 프레이밍을 위한 시작값이다.
광원은 카메라 뒤쪽의 확산광으로 유지하고 화면 반사, 직사광, 밝기 변동이 큰 조명은 피한다.

두 노트북은 가능하면 60Hz, 기본 해상도, HDR/야간 모드/자동 밝기 끄기, 1배속 전체 화면 재생을 쓴다.
60Hz를 지원하지 않으면 실제 설정을 기록한다. 마우스 커서·재생 컨트롤·알림을 화면 밖으로 치운다.
밝기 백분율은 기기별 설정값이며 두 패널의 실제 휘도가 같다는 뜻은 아니다.

| 조건 | 재생 화면 | 밝기 설정 | 촬영 각도 | 테이크 수 |
|---|---|---:|---:|---:|
| C1 | Pro | 70% | 정면 0° | 12 |
| C2 | Pro | 40% | 좌/우 약 20° | 12 |
| C3 | Ultra | 70% | 정면 0° | 12 |
| C4 | Ultra | 40% | 좌/우 약 20° | 12 |

원본 ID가 홀수이면 C1+C4, 짝수이면 C2+C3로 촬영한다. 각 원본이 두 화면을 모두 거치며 계획한 각 split에서도 조건이 균형을 이룬다.
각도는 회전 방향까지 notes에 적는다. 거리·ISO·WB·실제 Hz는 촬영 후 기록한다.
실험 규모가 작으므로 각도/밝기 영향을 독립적으로 추정하는 요인 실험으로 해석하지 않는다.

## S23 Ultra 설정

카메라 → 더보기 → **프로 동영상**에서 시작한다. One UI 버전에 따라 메뉴 이름과 제공 항목은 달라질 수 있다.

| 설정 | 시작값 / 이유 |
|---|---|
| 렌즈·방향 | 후면 기본 W/1×, 가로. 초광각/디지털 줌은 사용하지 않음 |
| 해상도·FPS | FHD 1920×1080, 30fps. 저장·검수 부담을 낮추는 초기 선택 |
| 셔터 | 1/60초. 넓은 검은 띠가 가리면 시험 단계에서 1/120도 비교하고 채택값 기록 |
| ISO | 100부터 시작, 50~400 범위에서 화면 흰 부분이 날아가지 않도록 조정 후 고정 |
| 화이트밸런스 | 5000K 부근에서 시작, 실내 광원에 맞춰 한 번 조정 후 고정 |
| 초점 | 화면에 맞춘 뒤 수동 초점 또는 초점 잠금 |
| 자동 기능 | Auto FPS, HDR10+, 고효율 HEVC, 슈퍼 스테디/전자식 안정화는 해당 옵션이 있으면 끄기 |
| 코덱 | 가능한 H.264/AVC. 저장 파일의 실제 코덱과 FPS는 전송 후 확인 |

지원하지 않는 옵션을 억지로 찾거나 존재한다고 가정하지 않는다. 설정값은 촬영 설계이며 Samsung의 최적값 보증이 아니다.
Samsung은 프로 모드의 ISO/WB 제어와 Auto FPS 기능을 설명한다. [공식 카메라 모드 안내](https://www.samsung.com/us/support/answer/ANS10001353/), [S23 카메라 안내](https://www.samsung.com/us/support/answer/ANS10003680/).

## 촬영 순서와 품질 판정

1. 시험 영상 3개로 차량 움직임·도로·주요 객체가 보이는지 확인한다. 약한 모아레/밴딩은 재촬영의 실제 특징으로 보존한다. 화면을 가리는 검은 띠·반사·초점 이탈은 재촬영한다.
2. 각 원본의 유효 내용 8~12초를 선정하고 시작/끝 시간을 표에 쓴다. 앞뒤 2초씩 여유를 두어 촬영한다.
3. 표의 output_filename과 실제 휴대폰 파일명을 대응시킨다. 실패 테이크도 덮어쓰지 않고 take02 등으로 구분한다.
4. USB 케이블 → 휴대폰 잠금 해제 → USB 파일 전송 → DCIM/Camera에서 원본 파일 복사. 카카오톡 압축 전송을 피한다.
5. 휴대폰 원본은 그대로 보존한다. 학습용 파생본에서만 동일 내용 구간과 화면 안쪽을 잘라 쓰고, 원본/재촬영 양쪽에 같은 리사이즈·인코딩 절차를 적용한다. 베젤·파일 코덱만 학습하는 것을 줄이기 위함이다.
6. 같은 출처의 ORIGINAL/RERECORDED를 같은 split에 둔다. 검증용 원본을 학습에 다시 넣지 않는다.

한 대의 S23 Ultra로 만든 데이터는 다른 휴대폰까지 일반화된다는 근거가 아니다. 검증 결과에는 기기 범위를 명시한다.

## 준비된 검수 파일

프로젝트 루트의 전용 Python으로 실행한다. 같은 세션명은 덮어쓰지 않으며 새 이름을 사용한다.

```powershell
& $pythonPath -m harness execute --profile pro360 --kind cpu --timeout 180 -- $pythonPath scripts/prepare_review_session.py --session pro_20260924 --with-frames
```

`$pythonPath` 정의와 선행 데이터 준비 명령은 PRO360_STEPS.md에 있다.
`data/derived/review_sessions/<session>/`에는 S2 후보 50개(정답 빈칸), S1 촬영표 48행, S3 검수표 20행과 source_<0기반 프레임번호>.jpg 20장이 생성된다.
S3 사진은 시각적 대조용이다. 사진만 보고 속도/조향 수치를 정답이라고 승인하지 않는다.
frame_offset_seconds, 영상 프레임 번호, 센서 구간과 보간 타깃을 함께 확인한다. comma 파일럿 검수는 공식 Baseline의 별도 시간축 문제 해결을 의미하지 않는다.
