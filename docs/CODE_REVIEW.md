# 전체 코드·자료 분석

## 공식 데이터 설명 추가 확인

data_description.md는 사용자가 공식 사이트의 Baseline 데이터 설명으로 지정했다.
별도 학습 데이터셋은 없으며 공개 예제는 코드 실행/입출력 점검용이다. 실제 평가 분포와 다를 수 있다.
S1 모사 재녹화, S2 미학습 세 항목, S3 희소 라벨이라는 기존 코드 분석을 공식 설명이 뒷받침한다.
비공개 S3 입력은 10Hz 영상이고 sample_index는 0부터 시작하는 0.1초 순번이다.
CAN은 정답 생성에만 사용되며 추론 입력으로 제공되지 않는다.
따라서 공개 S3 파일의 시간축 문제는 공개 예제의 정렬 검수 문제로 한정하며, 공식 평가 입력 계약은 확정된 것으로 취급한다.
원본 Baseline.zip과 노트북을 곧바로 제출하는 작업은 수행하지 않는다.

분석일: 2026-09-23. 원본 2개 노트북의 모든 셀과 requirements.txt를 읽었고,
overview/evaluation/범용 HTML/평가 그림, CSV 3개, 영상 20개의 파일·메타데이터를 확인했다.
Baseline.zip의 코드 구성도 확인했다. ZIP은 실행 소스가 추가된 별도 프로젝트가 아니라 배포 묶음이다.
영상은 첫/마지막 프레임 디코드 및 SHA-256을 확인했으며 모든 중간 프레임의 시각적 검수는 하지 않았다.
새 하네스 외에 숨겨진 별도 학습 스크립트나 계획 문서는 발견되지 않았다.

## 학습 노트북 (셀 번호는 0부터)

| 셀 | 내용 | 분석 |
|---|---|---|
| 0–2 | 설명, pip 설치, 제목 | requirements의 OpenCV GUI 패키지를 전역에 설치할 위험. 별도 venv/headless로 분리 |
| 3–4 | 라이브러리, ROOT, DEVICE, EPOCHS, 정규화, seed | cwd에 의존. torch/random seed만 설정, numpy/worker 및 실제 실험 기록 없음 |
| 5 | _video_frames, _crop_tensor, _clip | 매 샘플마다 원본 영상 전체 RGB를 메모리에 읽음. Stage 3 약 1200×1164×874×3 ≈ 3.4GiB/영상(배열 부가비용 제외), 라벨마다 반복 |
| 6 | Stage1MViT, Stage2Temporal, Stage3MViT | S1/S3 MViTv2-S는 무작위 초기화. S2 ResNet18 + 2층 양방향 GRU(192), 시점 2개/상황 헤드 |
| 7 | fit_stage1, _resnet_backbone, fit_stage2, fit_stage3 | 모든 학습·저장 구현. 검증 분할/early stopping/metrics 없음. best.pt는 실제 best가 아니라 마지막 상태 |
| 8–10 | 3개 Stage 순차 학습·파일 목록 | import와 실행 분리 없음. Windows spawn 환경의 안전한 CLI main guard로 이관 필요 |
| 11 | 빈 셀 | 실행 없음 |

- S1: 전체 영상에 균등하게 분포한 16프레임을 학습. 추론은 국소 연속 16프레임 3클립의 확률 평균이므로 시간 샘플링 분포가 다름. 추론 설명의 '로짓 평균'과 실제 확률 평균도 다르다.
- S2: t_collision을 int로 변환해 프레임 index로 직접 사용. 제공값 30–41은 50프레임 영상 안에 있지만 명칭 t_만 보고 초로 해석하면 안 된다. 시점 정의/원본 프레임 대응정보 확인 필요.
- S2: collision loss만 계산한다. entry 헤드와 scene 헤드에는 학습 신호가 없다. -1인 t_entry/evasion_space/entry_side를 0이나 정답으로 바꾸면 안 된다.
- S2: 사전학습 다운로드 실패를 잡아 무작위 백본으로 계속 진행하고 동일 파일명으로 저장한다. 후속 구현에서는 실패시키거나 초기화 출처를 명시해야 재현 가능하다.
- S3: 50개 희소 라벨의 frame_index 중심으로 클립을 학습. 관측되지 않은 프레임의 라벨을 정답으로 보간해서는 안 된다. STOPPED에서도 steer loss를 학습하지만 공식 조향 평가는 STOPPED를 제외하므로 분리 집계가 필요하다.
- S3: 학습은 짧은 변을 224로 맞춰 224 중앙 크롭, 추론은 짧은 변을 256으로 맞춰 224 중앙 크롭하므로 시야/공간 배율도 다르다. 시간축과 함께 전처리를 공유 모듈로 통일해야 한다.
- 공통: FP32 전체 학습/AdamW 상태로 8GB 사용량이 커질 수 있다. batch 1, AMP, gradient accumulation/부분 freeze는 후속 실험으로 검증하며 이번 smoke만으로 학습 가능성을 단정하지 않는다.

## 데이터 사실

| Stage | 공개 자료 | 주의점 |
|---|---|---|
| 1 | 원본 5 + 모사 재녹화 5, 각각 50프레임/10fps | 실제 기기 재촬영 데이터가 아님. 동일 원본-파생 쌍을 그룹화 |
| 2 | 영상 5, collision 라벨 5 | 나머지 3개 항목 전부 -1. S1 원본과 각각 SHA-256 동일 |
| 3 | 영상 5, 라벨 50 | 가감속 9/8/30/3, 조향 LEFT6/STRAIGHT39/RIGHT5. 불균형·희소 라벨 |

Stage 3의 frame_index/time_seconds는 20fps 관계다(120/6, 1080/54).
sample_index/time_seconds는 10Hz 관계다. 반면 OpenCV 컨테이너 메타데이터는 약 478.58–480.18fps,
약 1197–1201프레임/2.501초로 읽힌다. 이는 확인된 불일치이지 실제 촬영 FPS가 480이라는 결론이 아니다.
패키지 버전별 재확인, 원본 타임스탬프/공식 안내 확인 후 10Hz 변환 정책과 테스트를 결정해야 한다.
현재 예제를 그대로 복사해 S3 추론을 돌린 결과를 0.1초 단위 정확한 예측으로 평가할 수 없다.

## 평가 계약과 아직 확정하지 않은 사항

- 대회별 문서/노트북: inference.py의 predict_stage1/2/3 → DataFrame, model/stage1/2/3, requirements.txt. script.py는 서버가 추가한다.
- 범용 HTML: 참가자가 script.py를 넣는 일반 예시. 대회별 계약을 우선하되 실제 제출 전 최신 공식 공지로 확인한다.
- 전체 Stage 가중치 0.2/0.4/0.4, S1 Macro-F1, S3 STOPPED 조향 제외, 전 프레임 steer 출력은 확인됨.
- 세부 시점 오차/평가 수식은 첨부 그림 형태이며 현재 텍스트만으로 정확한 수치·집계식을 확정하지 않았다. 임의 평가 점수 구현하지 않음.
- 설치10분/추론60분/ZIP10GB/해제32GB, L40S44.7GiB/CPU7/RAM60GB. 패키저는 보수적으로 십진 GB 한도 적용.
- 현재 장비 검증은 Windows. Linux L40S에서의 설치·오프라인·성능·제한시간 준수는 추후 별도 게이트다.
