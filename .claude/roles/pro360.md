## 제약

- **디스크 여유가 약 22GB다.** 새로 만드는 데이터는 합계 5GB 이하로 유지하고, 임시 프레임은 `work/`에 두었다가 끝나면 지운다. 원본 영상을 통째로 복사하지 않는다.
- main checkout은 깨끗하게 유지한다(교환 worker가 fast-forward한다). 1회용 분석 스크립트는 `work/pro_tools/`(Git 제외)에 둔다. 공유할 코드는 worktree 브랜치 `pro/<topic>`에서 commit하고 `git push -u origin pro/<topic>` 한 뒤 Ultra에 `request` 패킷으로 병합을 요청한다.
- GPU 학습은 하지 않는다. 필요하면 Ultra에 `request`를 보낸다.

## 우선순위 (마감 역산)

1. **S2 에이전트 라벨 (가장 중요, 9/26 오전까지 1차분).** Nexar positive 80개에서 실제 접촉 사례를 찾아 라벨한다.
   - 영상 하나당 `frame-labeler` 서브에이전트를 쓴다(맥락 절약). 결과는 `scripts/stage2_agent_label.py add ...`로 기록한다.
   - 10개마다 `scripts/stage2_agent_label.py merge`로 병합본을 만들고, `qa` 패킷(`subject: "stage2 labels vN"`)에 병합 CSV·유효 수·confidence 분포·불확실 사례를 첨부해 Ultra에 보낸다. 첫 배치는 빨리 보낸다.
   - negative 24개는 사건 없음(`actual_contact=no`)으로 기록하되 collision 정답을 만들지 않는다.
   - 확신이 낮은 경우(confidence < 0.5)는 notes에 이유를 남긴다. 억지로 채우지 않는다.
2. **S1 합성 재촬영 데이터 (9/26 오전).** comma `s1_playback` 24개(+필요하면 같은 주행의 다른 구간)로 화면 재촬영을 흉내 낸 영상을 만든다: 원근 변형, 모아레·화면 격자, 감마·색온도, 반사·비네팅, 흐림·초점, 노이즈, 프레임레이트 변환, 재인코딩. **원본도 같은 최종 resize·인코딩을 거친** 짝을 만든다. 같은 source의 모든 파생물은 같은 split이다. 결과(각 파일 512MiB 이하)를 `qa` 패킷으로 보낸다. S23 실촬영 파일이 `data/captures/s23/`에 생기면 QA 후 별도 배치로 보낸다.
3. **S3 클래스 규칙 제안.** `s3_auxiliary_10hz.csv`의 train split에서 STOPPED 속도 임계값, 가감속 deadband, 조향 bias/threshold, 평활화 창을 정하고 클래스 분포를 보고한다(`qa` 패킷). SRC014 제외는 유지한다.
4. **Ultra result 검토.** `result` 패킷이 오면 같은 정답·metric으로 CPU에서 지표를 다시 계산하고(sample ID 조인, 누락·중복·split 혼입·프레임 범위 확인) `review` 패킷을 보낸다. `integrity_pass`, `metrics_reproduced`, `comparable_to_baseline`와 가장 큰 문제에 대한 **한 가지** proposal을 넣는다.
5. 사람이 CSV나 촬영 폴더를 바꾸면(`input_changed`) 반영한다. 사람 `reviewed` 라벨과 에이전트 라벨이 다르면 차이를 보고하고 사람 값을 쓴다.
